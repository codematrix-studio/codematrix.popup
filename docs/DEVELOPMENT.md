# Правила разработки и сопровождения

## Язык

- Документация для пользователей и разработчиков ведётся на русском языке.
- Комментарии в PHP, JavaScript, CSS и HTML пишутся на русском, если комментарий действительно помогает понять код.
- Новые и изменяемые комментарии пишутся на русском языке, если они поясняют нетривиальную логику.
- При техническом рефакторинге не выполнять попутный перевод или удаление комментариев, если это не относится к текущей задаче.
- Не добавляйте комментарии, которые лишь повторяют имя следующей функции или очевидную строку кода.
- Технические идентификаторы, имена API, классов, методов, функций, переменных, констант, CSS-классов, JS-событий, параметров и ключей массивов не переводятся.

## Безопасное изменение файлов

1. Перед редактированием получите актуальное содержимое файла из целевой ветки и его SHA.
2. Убедитесь, что файл не изменился с момента проверки.
3. Вносите минимальную тематическую правку. Не объединяйте перевод комментариев с рефакторингом логики.
4. После изменения повторно получите файл и проверьте итоговое содержимое.
5. Для PHP проверяйте синтаксис, для JavaScript — синтаксис и корректность подключений; отдельно проверяйте затронутые сценарии на тестовом сайте.
6. Не заявляйте о проверке на стенде, если она фактически не выполнялась.

## Что нельзя менять при языковой правке

- исполняемый код;
- имена и значения ключей, используемых программой;
- строки, передаваемые в API 1С-Битрикс;
- селекторы, CSS-классы и HTML-атрибуты, используемые JavaScript;
- тексты интерфейса, которые должны оставаться в языковых файлах `lang/`;
- содержимое минифицированных библиотек и сторонних ресурсов.

## Кодировка

Перед переводом комментариев проверьте кодировку файла. Если исходный файл содержит текст в нестандартной или некорректно распознанной кодировке, не пересохраняйте его целиком автоматически: это может повредить русские строки и данные. Сначала необходимо установить фактическую кодировку и подготовить безопасное преобразование.

## Происхождение проекта и границы репозитория

- Рабочий репозиторий: `codematrix-studio/codematrix.popup`.
- Первая версия CodeMatrix Popup создана на основе исходного кода репозитория [ASDAFF/fly.popup](https://github.com/ASDAFF/fly.popup). При разработке V2 этот репозиторий служит источником для проверки происхождения отдельных участков, восстановления контекста и документирования истории кода.
- Исходный репозиторий `ASDAFF/fly.popup` не изменяется.
- Снимок исходного репозитория, зафиксированный при старте V2: commit `0c0e9e7b1ae8c286174219bd13bb227cdb5c06c9`.
- Ветка `main` содержит контрольную версию V1. Разработка V2 ведётся в отдельной ветке `v2/d7-migration`.
- Каталог `source/skyweb24.popuppro/` не переносится и не используется как источник кода V2.

## Правила миграции V2

- Функциональность не расширяется и не сокращается: цель — сохранить поведение V1 при изменении внутренней архитектуры.
- До замены API фиксируются все места вызова, входные параметры, выходные значения, побочные эффекты и зависимости.
- Схема существующих таблиц и формат сохранённых настроек рассматриваются как контракт совместимости.
- Обновление V1 до V2 не должно удалять данные или требовать переустановки модуля.
- Не переписывать компонентный механизм Bitrix только ради формального перехода на D7.
- Не смешивать миграцию с новыми возможностями или несогласованными исправлениями дефектов.
- Все решения и результаты проверок заносить в `docs/V2_MIGRATION.md` и `docs/V2_BASELINE.md`.
