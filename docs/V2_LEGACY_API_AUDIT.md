# Аудит legacy API V2

Дата проверки: 2026-11-20  
Ветка: `v2/d7-migration`  
Репозиторий: `codematrix-studio/codematrix.popup`  
Базовое окружение стенда: PHP 8.2.30, Bitrix main 26.150.0.

## Назначение

Документ фиксирует инвентаризацию оставшихся вызовов legacy API после переноса операций с собственными таблицами модуля на D7 ORM.

Цель миграции — не механически удалить все старые классы Битрикс, а заменить те API, для которых есть подходящий D7-аналог без изменения поведения. Контракты административного интерфейса, компонентов, установщика, AJAX и формат хранимых настроек должны сохраняться.

На этом этапе выполнен первичный статический просмотр исходников ветки. Это не заключение о полном отсутствии других legacy-вызовов и не результат runtime-тестирования.

- `CSaleBasket::GetBasketUserID()` и `CSaleBasket::GetList()` — старый API корзины.
- `CCatalogSKU::getProductList()` — API каталога для сопоставления предложений и товаров.
- `CJSCore::Init()` — подключение штатных JS-расширений ядра.

Предварительная классификация:

## 2. AJAX и совместимость контрактов

Проверены точки входа:

- `admin/codematrix_popup_ajax.php` — обработчики `getPopups`, `getBasket`, `getTemplatePath`, `getHTML`, `statisticShow`, `statisticTime`, `statisticAction`.
- `install/admin/codematrix_popup_ajax.php` — установочный прокси к административному обработчику.
- `install/components/codematrix/popup.pro/templates/*/ajax.php` — AJAX-файлы шаблонов.

В административном AJAX используются `Application::getInstance()->getContext()->getRequest()`, но сериализация ответа пока выполняется через `CUtil::PhpToJSObject()` с дополнительной заменой кавычек. Это требует отдельного анализа: нельзя заменять JSON-сериализацию, пока не зафиксированы фактические ответы и ожидания JavaScript.

Нужно сохранить имена действий, параметры, структуру ответов, кодировку, обработку ошибок и статистические события.

## 3. API, которые не следует заменять автоматически

- `CModule` в установщике — базовый механизм жизненного цикла модуля.
- `CBitrixComponent` и `CAdmin*` — штатные контракты компонентной и административной подсистем.
- `CDBResult` — пока используется как адаптер для совместимости административной навигации с результатом ORM.
- Legacy API без прямого D7-эквивалента с идентичным контрактом нельзя заменять формально только ради удаления старых имён.

## 4. Приоритет дальнейшего аудита

1. Пользователи и группы: `CUser`, `CGroup`, проверка сценариев регистрации и назначения групп.
2. Инфоблоки: `CIBlockType`, `CIBlock`, `CIBlockProperty`, `CIBlockElement`.
3. Файлы: `CFile`.
4. Sale: `CSaleDiscount` и оставшийся `CModule::IncludeModule()`.
5. DDL и lifecycle установщика: D7 Connection при сохранении install/uninstall contract.
7. Проверка всех AJAX-контрактов и runtime-сценариев.
8. Повторный поиск legacy-вызовов по всей PHP-части проекта и итоговая сверка с V1.

## 5. Ограничения проверки

- В рамках продолжения аудита почтовая подсистема переведена на D7; остальные подсистемы пока не изменялись.
- `main` и исходный репозиторий `ASDAFF/fly.popup` не изменялись.
- Функциональность не расширялась.
- Статический просмотр исходников не заменяет PHP lint и проверку на стенде.
- Все замены должны сопровождаться сравнением поведения с V1 и тестами на PHP 8.2.30 / Bitrix main 26.150.0.


## 6. Выполненная миграция почтовой подсистемы

Дата: 2026-11-20. Ветка: v2/d7-migration.

Добавлен lib/mail.php — единая D7-обёртка CodeMatrix\\Popup\\Mail:

- EventTypeTable — поиск, регистрация и удаление типов почтовых событий.
- EventMessageTable — чтение, создание и удаление почтовых шаблонов.
- EventMessageSiteTable — привязка одного шаблона к нескольким сайтам. Сохранена модель Битрикс: одна запись шаблона и отдельные строки связей с сайтами, без дублирования шаблона для каждого сайта.
- Bitrix\\Main\\Mail\\Event::send() — отправка почтовых событий.

Обновлены:

- classes/general/popup.php — получение шаблонов купона, рулетки и скидки.
- classes/general/popup_edit.php — создание типов событий и шаблонов при создании попапов, а также шаблона контактной формы.
- lib/tools.php — список почтовых шаблонов для вспомогательного API.
- install/index.php — установка и удаление типов событий и шаблонов.
- install/components/codematrix/popup.pro/class.php — отправка заявки через D7 Mail Event.
- include.php — регистрация автозагрузки сервиса.

Сохранены коды событий, макросы, тема письма, тело, формат HTML/text, адреса отправителя/получателя, ID шаблона, флаг DUPLICATE и привязка шаблонов к сайтам. Для Event::send() параметр LID передаётся строкой, как требует D7 API; LANGUAGE_ID передаётся явно, как в legacy-вызове CEvent::Send.

Проверка по исходникам подтверждает наличие D7 ORM-сущностей EventTypeTable, EventMessageTable, EventMessageSiteTable и их полей/связей. Изменения закоммичены и каждый изменённый файл повторно получен из GitHub для проверки содержимого.

Не выполнено: PHP lint и runtime-проверки на стенде. Их нельзя считать пройденными без запуска на целевом Bitrix 26.150.0. Нужно проверить создание/чтение шаблонов на нескольких сайтах, отправку с заданным MESSAGE_ID, установку на чистой базе и удаление только шаблонов модуля.

## 7. Миграция чтения пользователей

Дата: 2026-11-20. Ветка: `v2/d7-migration`.

В `install/components/codematrix/popup.pro/class.php` заменены два запроса чтения пользователей:

- `CUser::GetByID()` заменён на `Bitrix\\Main\\UserTable::getById()->fetch()` при заполнении контактных данных авторизованного пользователя.
- `CUser::GetList()` заменён на `UserTable::getList()` с точным фильтром по EMAIL и сортировкой по ID DESC в сценарии регистрации контактной формы.

Изменение закоммичено в ветку V2 (commit `aa2441d55479bed75b338967ce40107970efb3e2`). Файл повторно получен из GitHub; подтверждены импорт `UserTable` и отсутствие в нём указанных двух legacy-методов.

Не выполнено: PHP lint и runtime-проверка на стенде. Остались legacy-операции изменения пользователя и групп, включая `CUser::SetUserGroup()`, `CUser::GetUserGroup()`, создание/обновление через `CUser` и пользовательский метод `$USER->SimpleRegister()`. Их нужно анализировать отдельно: не заменять регистрацию и изменение групп до фиксации побочных эффектов и проверки D7-контрактов.

## 8. Миграция запросов пользователей и связей с группами в discount_default

Дата: 2026-11-20. Ветка: `v2/d7-migration`.

В `install/components/codematrix/popup.pro/templates/discount_default/ajax.php` выполнены следующие замены:

- Поиск пользователя по EMAIL через `CUser::GetList()` заменён на `UserTable::getList()` с тем же условием и сортировкой по ID DESC.
- Чтение текущей связи пользователя с группой и добавление недостающей связи выполняются через `UserGroupTable`; существующие группы не удаляются.

Создание/обновление пользователя через `CUser`, авторизация через `$USER->Authorize()` и пользовательский метод `$USER->SimpleRegister()` оставлены без изменений: их поведение требует отдельной проверки, и механическая замена на ORM может изменить регистрацию и побочные эффекты.

Изменение закоммичено: `b0a8f9e03532332e1f29c11248a77396b6560c5d`. Файл повторно получен из GitHub; подтверждены D7-запрос пользователя и D7-операции со связью группы, указанные legacy-вызовы чтения/назначения групп отсутствуют.

Не выполнено: PHP lint и runtime-проверка на стенде. Результат `UserGroupTable::add()` пока не обрабатывается; перед выпуском нужно проверить сценарий на валидной группе и корректность ответа при ошибке добавления.

Не выполнено: PHP lint и runtime-сверка списка групп и порядка сортировки на стенде Bitrix 26.150.0.


## 10. Миграция свойств инфоблоков во вспомогательном API

Дата: 2026-11-20. Ветка: `v2/d7-migration`.

В `lib/tools.php::Tools::returnPropId()` заменены `CIBlockProperty::GetList()` и `CIBlockProperty::Add()` на D7 `Bitrix\\Iblock\\PropertyTable`:

- Поиск выполняется по прежним ключам `IBLOCK_ID` и `CODE`; код свойства по-прежнему приводится к верхнему регистру.
- При отсутствии свойства создаётся строковое активное свойство с теми же NAME, SORT=100, CODE, PROPERTY_TYPE=S и IBLOCK_ID.
- Метод возвращает ID найденного/созданного свойства либо `false` при ошибке D7 add.

Не выполнено: PHP lint и runtime-проверка поиска существующего свойства, создания нового свойства и поведения при ошибке ORM на Bitrix 26.150.0.
